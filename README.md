# 조각로그 · Mosaic Log

대사와 나레이션을 꾸미고, 완성한 로그를 HTML로 내보내는 웹 도구입니다.

[바로 사용하기](https://mosaic-log.github.io/) · [업데이트 내역](https://github.com/mosaic-log/mosaic-log.github.io/releases) · [오류 제보·제안](https://github.com/mosaic-log/mosaic-log.github.io/issues)

## v1.10.0

- 원문 병행의 방식에서 미적용·괄호 번역·문단 번역 중 하나를 선택합니다. 방식과 배치는 기존 드롭다운·좌우 화살표 형식을 유지하며 두 번역 방식은 동시에 적용되지 않습니다.
- 괄호 번역과 문단 번역은 모두 대사·나레이션에 함께 적용합니다. 별도 대상 선택 없이 사용하며, 괄호 번역의 예외는 미리보기에서 개별 제외합니다. 도움말은 선택한 방식에 맞춰 표시합니다.
- 문단 번역은 카드마다 처음 언어를 판별할 수 있는 본문 문단의 언어를 원문 언어로 정합니다. 첫 문단이 영문이면 영문→한글, 한글이면 한글→영문 순서만 짝으로 묶습니다. 반대 순서의 문단은 일반 출력으로 유지하고, 같은 원문 언어가 이어지면 바로 뒤 번역과 맞는 문단만 묶습니다. 입력 원문은 재정렬해 저장하지 않습니다.
- 유효한 문단 쌍의 첫 문단이 원문, 둘째가 번역입니다. 원문 우선은 첫 문단, 번역 우선은 둘째를 먼저 표시하고 기존 색상·크기로 강조합니다. 표시 순서를 바꿔도 기준 언어는 유지합니다.
- 구분선·접기·문단 종류 변경은 앞뒤 짝을 끊으며, 카드의 기준 언어는 유지합니다. 새 카드에서는 기준 언어를 다시 정합니다. 표시 순서 설정은 이미 찾은 쌍 안에만 적용합니다.
- 언어는 본문의 문자로 판별하며 화자·등록된 인물 이름·이름 치환 문구·색상 표시·URL은 제외합니다. 문장 속 인용은 바깥 문장을 기준으로 판단하고, 인용만 있으면 그 내용을 봅니다. 판별 대상에 한글이 있으면 한글 문단으로 봅니다. 숫자·기호만 있거나 판별할 수 없는 문단에서는 짝을 새로 시작합니다.
- 우선 문단은 기존 크기·색상을 유지합니다. 보조 나레이션 문단은 0.5px 작게, 대사 아래 보조문장은 괄호 번역과 같은 대사 크기의 90%로 표시합니다. 기존 번역 보조색을 사용하고 최소 크기 9px와 줄간격 설정을 유지합니다.
- 대사 쌍은 우선 문장에만 기존 표현과 화자 이름을 적용합니다. 보조 대사는 아래의 별도 문단에 장식 없이 표시하며 기본 굵기는 보통입니다. 한쪽의 화자 표시는 쌍에서 공유하고, 서로 다른 화자가 명시되면 짝을 새로 시작합니다.
- 대사 앞뒤에 서술이 붙은 문단도 대사 쌍으로 처리합니다. 보조 쪽은 서술과 대사를 한 문단으로 보존하고 대사 크기의 90%를 적용합니다. 서술은 나레이션 보조색, 따옴표 속 대사는 해당 화자의 보조색으로 구분하며 직접 넣은 강조는 유지합니다. 우선 쪽은 기존 대사 표현을 사용하며, 한 문단 안에 서로 다른 화자가 명시되면 짝으로 묶지 않습니다.
- 쌍 안 문단 간격은 기존 간격의 80%로 조정합니다. 완성된 쌍 뒤의 여백은 13.5px에서 기존 간격+16px를 유지하고, 해당 쌍의 글자 크기에 비례합니다. 나레이션 쌍은 나레이션 크기, 대사·속마음 쌍은 대사 크기를 따릅니다. 카드 끝에는 추가하지 않으며, 구분선·이미지·접기 같은 구조 경계의 여백은 유지합니다.
- 구분선·이미지·소제목·인용·메모·접기 경계와 문단 종류 변경에서 짝을 새로 시작합니다. 남은 한 문단은 일반 출력으로 유지합니다.
- 투명 테마는 기존처럼 게시판 글자색을 따릅니다.

## 사용 방법

1. [조각로그](https://mosaic-log.github.io/)에 접속합니다.
2. 본문 탭에서 글을 입력합니다. 본문 문법은 작업 화면의 안내를 참고합니다.
3. 표지·디자인·테마 탭에서 필요한 항목과 모양을 설정합니다.
4. 미리보기에서 결과를 확인하고 수정합니다. 문장을 직접 편집할 때는 `Enter`로 저장하고 `Esc`로 취소합니다.
5. **HTML 복사하기**로 완성한 HTML을 복사해 게시글 작성기의 HTML 모드에 붙여넣거나, **HTML 저장하기**로 파일을 저장합니다.

표지나 프로필에 사진을 넣으려면 해당 항목에 이미지 URL을 입력합니다.

코멘트도 `[접기 제목]`과 `[/접기]`를 각각 독립된 줄에 입력해 일부를 접을 수 있습니다. 코멘트의 접기는 별도 장식 없이 브라우저 기본 `details`·`summary`로 표시합니다. 제목을 생략하면 ‘접기’로 표시하고, 닫는 문법을 생략하면 코멘트 끝까지 묶습니다. 본문 카드의 접기 디자인은 유지합니다.

코멘트 입력창의 엔터와 빈 줄은 출력 HTML의 `<br>`로 유지합니다. 직접 입력한 `<br>`·`<br/>`·`<br />`도 줄바꿈으로 표시하며, 다른 HTML 태그는 일반 글자로 표시합니다. 정돈 기능은 본문 카드에만 적용하고 코멘트의 줄바꿈과 내용은 보존합니다.

코멘트 입력창의 `Shift+Enter`도 줄바꿈으로 반영합니다. 미리보기 직접 편집에서는 기존처럼 `Enter`로 저장하고, `Shift+Enter`로 `<br>` 한 개에 해당하는 줄바꿈을 넣습니다.

## 저장과 백업

현재 작업은 사용 중인 브라우저에 자동 저장됩니다. 작업을 따로 보관하려면 보관함에 저장합니다. 다른 기기나 브라우저로 자동 동기화되지는 않습니다.

보관함은 초안·프리셋과 분리된 브라우저 저장 공간을 사용합니다. 목록 정보와 로그 내용을 나누어 저장하며 목록·검색은 본문 전체를 읽지 않습니다. 로그를 불러오거나 덮어쓸 때는 해당 항목만 처리합니다.

이전 보관함은 전체 검증 후 한 번에 이관하고 원본은 지우지 않습니다. 이관 중 저장 공간이 부족하거나 중단되면 부분 이관을 남기지 않으며 다시 시도할 수 있습니다. 원본과 새 자료를 함께 보관하므로 이관에는 추가 저장 공간이 필요합니다. 브라우저에서 사이트 데이터 저장을 허용해야 합니다.

보관함의 **내보내기**로 기존 형식의 JSON 백업을 만들고 **파일 가져오기**로 복원할 수 있습니다. HTML 저장하기·불러오기는 개별 작업을 옮길 때 사용할 수 있습니다.

현재 자료가 빠지거나 손상되면 구본을 자동으로 되살리지 않습니다. 원본 백업에서는 이관 전 사본·이전 저장소 사본을 구분하며, 현재 남은 레코드를 내보내는 복구 자료에는 불완전할 수 있음을 표시합니다. 두 현재 저장소가 모두 비었을 때는 JSON 가져오기에서 확인 후 복원할 수 있습니다.

구버전 탭은 새 화면으로 새로고침한 뒤 사용합니다. 구버전이 이전 localStorage 자료를 바꾸면 안내하며 자동으로 합치지 않습니다. 필요한 자료는 구버전에서 JSON으로 내보낸 뒤 가져옵니다. 다른 탭에서 같은 로그를 먼저 바꿨으면 오래된 저장·되돌리기를 거절하고, 다른 로그의 변경은 유지합니다.

보관함 항목은 누른 시점에 최신 내용을 다시 조회합니다. 삭제된 항목은 목록을 갱신하고, 조회 중 작업을 수정하면 불러오기를 취소합니다.

보관함 JSON은 파일당 32MB·200개 기준에 맞춰 필요할 때 자동으로 나눕니다. 분할 내보내기는 최대 10개씩 묶되 파일 크기도 함께 확인합니다. 색상 프리셋은 기존 512KB·100개 기준으로 나눕니다. 여러 파일로 저장됐다면 각 파일을 가져옵니다.

개인용 HTML은 앞부분의 복원 정보를 읽어 불러옵니다. 출력 부분이 커도 복원할 수 있으며, 복원 정보의 읽기 한도는 32MB입니다. 예전 예시를 바탕으로 작성한 초안도 자동 삭제하지 않습니다.

## 내려받아 실행하기

1. [Releases](https://github.com/mosaic-log/mosaic-log.github.io/releases)에서 압축 파일을 내려받습니다.
2. 압축을 모두 해제하고 같은 폴더의 `index.html`을 브라우저에서 엽니다.

설치·빌드 과정은 없습니다. HTML·CSS·JS 파일을 같은 폴더 구조로 유지합니다. 웹폰트와 이미지 URL은 인터넷 연결이 필요하며, 웹사이트와 로컬 파일의 저장 공간은 다릅니다.

## 현재 동작

- 원문 병행은 따옴표 밖 번역과 따옴표 안 끝 괄호 번역을 지원합니다. 중간 부가 설명과 공백뿐인 괄호는 번역으로 분리하지 않습니다. 괄호 번역과 문단 번역은 모두 대사·나레이션을 함께 처리합니다.
- 원문이나 번역에 `[BR]` 줄바꿈이 있어도 미리보기 편집에서 입력 순서를 보존합니다. 대사를 감싼 굵게·기울임과 `#` 없는 색상 표시도 출력과 편집에 함께 반영합니다.
- 같은 줄의 원문·번역 사이는 한 칸 띄우고 개별 제외·다시 적용을 지원합니다. 제외한 내부 괄호 문장은 원래 표기를 보존합니다.
- 본문·코멘트 이미지의 크기는 각 영역 폭 기준의%입니다. HTML 복사·저장도%를 유지하며 px 변환은 하지 않습니다.
- 표제로 끝나거나 개별 배치에서 코멘트가 이어지는 경계는 하단 모서리와 여백을 마감하고 불필요한 구분선 버튼을 숨깁니다.
- 메모와 인용은 줄인 안쪽 여백을 사용하며 메모 테두리는1px입니다.
- 스크롤바는 외부6px·내부4px의 웜그레이이며 호버해도 두께는 그대로이고 색상만 바뀝니다. 편집 패널 전체 스크롤도 같은 외부 스타일을 사용합니다. 기본색은 #D8D5CF, 호버색은 #96928A입니다. 고대비 모드에서는 시스템색을 우선합니다. 픽셀 두께는 WebKit 스타일 지원 환경 기준입니다.
- 폭 조절 경계는 호버·드래그·키보드 포커스에서 각진3px 강조선으로 표시합니다.
- 미리보기 도구는 실제 영역 폭과 버튼 폭을 재서 배치합니다. 두 줄에도 들어가지 않으면 상단 설정을 `⋯` 메뉴로 모으며, 배치 전환만으로 메뉴를 열지는 않습니다. 스크롤 중 다시 띄운 좁은 도구모음은 손잡이에 마우스를 올리면 제목·`⋯` 없이 항목 목록을 바로 보여줍니다. 접기 카드가 있으면 모두 열기·모두 접기도 상단 `⋯` 메뉴와 호버 목록 안에서 사용할 수 있습니다. 좁은 모드의 바깥에는 미리보기 제목과 `⋯` 한 줄만 남습니다. 넓은 모드에서는 접기 조작이 기존 위치로 돌아옵니다. 포인터 이탈·바깥 클릭·Esc로 닫고, 키보드나 터치로도 손잡이를 열 수 있습니다.
- PC 편집 패널은 340~760px 범위에서 조절하며, 미리보기 영역에 320px를 남기는 기준으로 창 너비에 따라 최대 폭을 제한합니다. 621~659px의 좁은 PC 화면에서는 편집 패널 최소 폭 340px를 우선합니다. 창을 일시적으로 줄여도 저장한 폭은 유지하고, 다시 넓히면 가능한 범위에서 복원합니다.

더보기 메뉴의 모양·폭은 현재 값만 표시하며, 모양·폭과 좌우 반전·전체 화면을 각각 한 줄로 묶습니다. 글자 크기와 32px 버튼 높이는 유지하고, 켜진 설정은 체크로 구분합니다.

PC·모바일 배치 전환 기준은 620px입니다. 621px 이상은 좌우 배치, 620px 이하는 세로 배치를 사용합니다.
